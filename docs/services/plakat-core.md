# plakat-core

## 1. Responsibility

The library module: everything a consumer of plakat-ui depends on. Today it is the build and nothing
else. It compiles for Android, iOS (`iosArm64`, `iosSimulatorArm64`), desktop JVM and wasmJs, and its
desktop test suite composes off-screen (B-01). Tokens, the generator and raskat ports, print
primitives, icons and the components land here item by item (backlog stages 0–2).

It deliberately does **not** depend on any Material artefact (research D1). The sample kit is the
`sample` module beside it, a consumer of the public API only. It is not published yet (B-37).

## 2. API contracts

The tokens (B-08) are the first public API; `plakat-core/api/` holds the ABI dump that `check` holds
every change to.
Packages are `io.github.youndie.plakat.*` (research D1).

## 3. How it is built

The build is toon-ui's, cut down to one library module and a sample. `io.github.youndie.sborka.settings`
supplies the repositories and the `wip` version catalog, so the Kotlin compiler, AGP and Compose
Multiplatform versions are a sborka bump, never a line here. `sborka.kmp` sets the toolchain and
compiler flags, explicit API and warnings-as-errors included. `sborka.lint` runs ktlint against the
portfolio's `.editorconfig`.

The AGP KMP library plugin is declared, unapplied, in the root build. The Compose plugin can only see
AGP's extension types when both are in the same build classloader. oldge-ui, kvadrant-ui and toon-ui
each met this once.

## 6. Local setup

```bash
export JAVA_HOME=$(/usr/libexec/java_home -v 25)
make check          # needs Node 20+ for the goldens check
./gradlew check
./gradlew :sample:run
```

On the Mac, not on the Linux box (research D12): the project is not in `mutagen sync list`, and the
screenshot goldens to come are a claim about the Mac's rasteriser. `check` also runs the iOS simulator
tests, so Xcode's simulator runtime has to be installed. `local.properties` names the Android SDK; it
is not committed.

## 7. Configuration

None at runtime.

not run it, because the output is committed and pinned by the metrics test.

## 8. Quirks

- `compileIosMainKotlinMetadata` and its two siblings compile without warnings-as-errors. CMP 1.12
  brings two lifecycle klibs with one `unique_name` into the shared iOS metadata, and the loader's
  warning about it is not this module's to fix. The per-target iOS compilations keep `-Werror`.
- `./gradlew check` does **not** compile `iosArm64` or Android main. Those are
  `:plakat-core:compileKotlinIosArm64` and `:plakat-core:compileAndroidMain`, run by hand in B-01. A
  change that breaks only a device target passes `check`.
- Common test names must not contain a comma: Kotlin/Native refuses the name, JVM accepts it.
- The texture tiles are @2x and are laid at half their pixel size (512 px = 256 dp, the Textures
  page), the non-print included. `plakat/print/nonprint/tile` says 200: that is the Tokens page's
  SVG recipe for it, not the delivered PNG, which the Textures page lays at 256.
- An icon is a `PlakatStencil`, not an `ImageVector`. Compose's vector parser turns an SVG arc into
  cubics, Skia flattens those differently from the conics Chrome draws an arc with, and the five round
  icons differed from their cells by up to 81 levels on the edge (Search 24: 5.73 %). The stencil's
  own walker draws arcs with `Path.arcTo`, conics on Skia: 46 of 48 cells at 0.00 %, Settings 48 and
  Error 48 at 0.17 % and 0.04 % (5 pixels, single-pixel antialiasing where Chrome's SVG `arcTo`
  segments its conics differently; the common `Path` has no `conicTo`). The walker takes moves, lines
  and unrotated arcs only, and `scripts/icons.mjs` refuses an icon with anything else.
- A button's pressed and focused cells are fixtures with the look forced (`ButtonLook`), since the
  page draws them as static pictures; the behaviour behind them is held by `PlakatButtonTest`.
- Only the ground and the shift of a button are transitions on release; the slogan's colour changes
  the moment the finger lifts, as CSS transitions `background-color` and `transform` only.
- Text whose baseline Chrome places is laid out with `cssLine` (`PlakatTypography.kt`): Blink rounds
  ascent and descent each and floors the half-leading, Compose centres the unrounded metrics, and a
  field's text and an error message stood a pixel low (TextField Error 5.80 % → 3.16 %). The face
  metrics it uses are held to the font files by `CssLineTest`. The button's labels already sat on
  Chrome's pixel and do not use it.
- On the web a texture arrives a frame late (an empty bitmap first); the layers draw nothing until
  the tile has loaded, so the first frame is the flat form.
- Multi-line text with a fractional line height cannot sit where Chrome puts it. A title of 17 px at
  1.25 has 21.25 px lines: Blink places each line box on the fraction and draws each baseline on a
  pixel (lines 0, 21, 42 after the first), while Compose lays each line on whole pixels — 22 apart
  through `LineHeightStyle`, so the paragraph is 66 px for Chrome's 63.75. From the second line the
  text is a pixel low, and anything centred against the paragraph moves (the Card Default cell's
  thumbnail, 2 px). It is the text layout, not the component; two-line titles happen to agree.
- `PlakatCard` takes a `RowScope` slot, because the page draws a card only as a row (a 64 dp
  thumbnail, then the text). A card prints whenever it enters the composition: in a lazy list, an
  item that scrolls back in prints again unless `printOrder` is null. Its tear clips the card to its
  own place, as the page's `overflow: hidden` wrapper does, so it leaves the slot's right edge; the
  gap a list puts between cards stays while the place closes, as on the page.
- A hidden snackbar's words go at once and only the plate rides down: the lab transitions the words'
  `clip-path` only on the way in (`clipTr` is `none` when hiding), which "уезжает вниз тем же путём"
  leaves open. The plate itself is not clipped; the screen edge it stands near hides what has ridden
  off, as the lab's `overflow: hidden` stage does.
- The poster draws its words line by line, each a one-line layout of `normal` height (`cssLine`) set on
  the baseline Blink computes for its line box (`floor` of the half-leading plus the rounded ascent).
  A paragraph laid out by Skia puts fractional lines on whole pixels, and a layout's reported
  `firstBaseline` is a fraction off the one Compose draws; upright, the baseline is put on a whole
  pixel as Blink does, turned to −17° it keeps the fraction. That took the posters from 2.2–4.2 % to
  1.1–2.8 %.
- The posters' composition is the Core page's own `comp`, not `plakat-gen.js` (research §1), so the
  page's posters can be reproduced at all; the card thumbnails take it too. Its circle can fall half off
  the poster (seed 47: 312 + 136 > 390), and a raskat there shows its seam near the poster's edge.
- IconButton's pressed cell on the MVP page draws no shift, though the spec row (and the FAB's cell) says
  `иконка +1 dp`: the live press follows the row, the forced look of the fixture follows the cell.
- A badge's width comes from the number's real width (`getLineRight`), rounded as Blink snaps a box: a
  layout's own width is ceiled, a pixel too wide (3.95 → 2.52 %). It is the target's, so the plate
  stands still through a tick.
- A FAB's ride starts where its left side is just past the window's right edge, measured from where it
  is placed, so any margin works. The spec row's «по оси −17° из-за правого нижнего края» cannot be
  met whole: that axis rises to the right, so past the right edge it is above the FAB, not below. The
  axis is kept (the kit's one diagonal, `plakat/shape`), and the owner reviews it.
- Flex items centre by themselves, so what sits beside text in a row is placed separately: inside a
  `Row` the chip's wedge centred within the 15 dp line and rounded a pixel low.
- A `Canvas` is a `Spacer`, which draws in nothing when it has only a minimum to go by: a `defaultMinSize`d one
  reports its size and stays empty. The circular progress is a `Box` for that; the fixtures, which size it,
  could not see it, the tests of it at its default size did.
- The page's loop (`plspin`) runs on the page's own switch, not on the media query, so the renderer stops every
  animation at its first frame before shooting; without it the spinner's reference was whatever the clock said.
- A display line shorter than its face (Rubik 32 at `line-height: 1`, a face of 40) is beyond `cssLine`, whose
  leading goes negative: it is laid out as a `normal` line and lifted by what the CSS line takes off the top.
- Like the posters' `comp`, the top app bar's strip is the page's own `raport`, not `plakat-gen.js`'s `rapport`: its
  red is chosen differently. A strip's circles are boxes on `1.5 px`, which Blink snaps to the pixel before
  rounding their corners.
- Short capitals at 11 px are the worst case for the text floor: the navigation bar's words are 59–82 % of their
  ink against 63.7 %, with no whole-pixel shift better. Chrome draws the cap's top row full where Compose
  draws it partly, and keeps each glyph's fractional x; viddik does not see `FontRasterizationSettings`.
  Named in B-26's findings as a gap, not closed.
- A row of equal slots is laid out by hand where it must match the page: `weight` hands out whole pixels, the page's
  grid keeps 97.5 and each child is placed from the true slot.
- The klib ABI dump lists the compose compiler's `$stableprop` of internal classes too; adding an
  internal class changes it and needs `updateKotlinAbi`.
